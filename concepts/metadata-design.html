SECTION 01
('Why Metadata Matters', "Two chunks may be equally similar to a query by embedding distance, but only one is from a verified source published this year. Without metadata, you can't distinguish them. Good metadata enables: filtered retrieval (only documents from source X), temporal filtering (after date Y), access control (user can only see their tenant's documents), and attribution (show the user which document the answer came from).")
SECTION 02
('Metadata Taxonomy', 'Provenance: source URL, document title, author, publication date, version. Structure: chunk index, section heading, page number, document type (PDF/HTML/code). Content: summary, keywords, entity types, language, topic category. Access control: tenant ID, user group, permission level. Quality: confidence score, last verified date, human-reviewed flag.')
SECTION 03
('Schema Design Principles', 'Design for query patterns, not for completeness. "\n "Ask: what filters will users apply? What attribution do they need? "\n "Keep metadata values low-cardinality for filters (5–20 unique values) "\n "or store as lists for multi-value attributes. Avoid free-text metadata fields "\n "that you\'ll try to filter on — normalise to enums or IDs instead.\n\nfrom pydantic import BaseModel\nfrom datetime import date\nfrom typing import Optional\n\nclass ChunkMetadata(BaseModel):\n # Provenance\n source_url: str\n doc_title: str\n author: Optional[str] = None\n published_date: Optional[date] = None\n # Structure\n chunk_index: int\n section: Optional[str] = None\n page_number: Optional[int] = None\n doc_type: str # "pdf", "html", "markdown", "code"\n # Access\n tenant_id: str\n is_public: bool = False\n # Quality\n human_reviewed: bool = False')
SECTION 04
('Filtering at Query Time', 'Use metadata filters to narrow the search space before or alongside vector similarity. "\n "Most vector stores support hybrid filtering (metadata + vector).\n\nfrom qdrant_client import QdrantClient\nfrom qdrant_client.models import Filter, FieldCondition, MatchValue, Range\n\nclient = QdrantClient("localhost", port=6333)\n\nresults = client.search(\n collection_name="documents",\n query_vector=query_embedding,\n query_filter=Filter(\n must=[\n FieldCondition(key="tenant_id", match=MatchValue(value="acme-corp")),\n FieldCondition(key="doc_type", match=MatchValue(value="pdf")),\n FieldCondition(key="published_date",\n range=Range(gte="2024-01-01")),\n ]\n ),\n limit=10,\n)')
SECTION 05
('Embedding Metadata', "For richer semantic retrieval, embed metadata alongside content: prepend document title, section heading, and keywords to the chunk text before embedding. '[Title: Annual Report 2024] [Section: Revenue] Q4 revenue was $1.2B...' This shifts the embedding toward the document's semantic context, improving retrieval for queries like 'what were Q4 revenues?'")
SECTION 06
('Tooling & Standards', 'LangChain Document: standard metadata dict attached to every Document object. LlamaIndex: rich metadata with per-field embedding control. Unstructured.io: auto-extracts metadata from PDFs, HTMLs, and Office docs. Dublin Core: standard for provenance metadata (title, creator, date, format). Keep metadata versioned alongside the corpus — schema changes require re-ingestion.')
