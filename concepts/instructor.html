SECTION 01

Raw text to typed objects

Without Instructor, getting structured data from an LLM looks like:

  1. Ask the model to return JSON.
  2. Parse the JSON string.
  3. Check the types manually.
  4. Handle the case where the model returned markdown fences, or the wrong keys, or a string instead of a number.
  5. Retry and hope.

With Instructor, that entire workflow collapses into one function call that returns a typed Python object. Validation, retries, and error messages are handled for you.

SECTION 02

How Instructor works

Instructor patches the LLM client to:

  1. Convert your Pydantic model's JSON schema into a tool definition or JSON mode instruction.
  2. Make the API call.
  3. Parse the response and validate it against the Pydantic model.
  4. If validation fails, send the validation error back to the model as a follow-up message and retry (up to max_retries times).

The retry prompt is automatically constructed from the Pydantic ValidationError, so the model sees exactly what went wrong and why.

SECTION 04

Your first extraction

from pydantic import BaseModel, Field
import instructor, anthropic

client = instructor.from_anthropic(anthropic.Anthropic())

class Person(BaseModel):
    name: str = Field(description="Full name of the person")
    age: int  = Field(description="Age in years, must be positive", gt=0)
    city: str = Field(description="City of residence")

person = client.messages.create(
    model="claude-3-5-haiku-20241022",
    max_tokens=256,
    messages=[{
        "role": "user",
        "content": "Extract info: Dr. Sarah Chen is a 41-year-old cardiologist based in Boston."
    }],
    response_model=Person,   # ← this is the Instructor extension
)

print(person.name)  # Dr. Sarah Chen  (type: str)
print(person.age)   # 41              (type: int)
print(person.city)  # Boston          (type: str)

The return type of client.messages.create is now Person, not a Message object. Full type-safety, no manual parsing.

SECTION 05

Nested models and lists

from pydantic import BaseModel
from typing import Optional
import instructor, anthropic

client = instructor.from_anthropic(anthropic.Anthropic())

class Address(BaseModel):
    street: str
    city: str
    country: str

class Company(BaseModel):
    name: str
    industry: str
    headquarters: Address
    employee_count: Optional[int] = None   # null if not mentioned

class MeetingNotes(BaseModel):
    date: str
    attendees: list[str]
    action_items: list[str]
    companies_mentioned: list[Company]

notes = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=1024,
    messages=[{"role":"user","content": meeting_transcript}],
    response_model=MeetingNotes,
)

for item in notes.action_items:
    print(f"TODO: {item}")

Instructor handles arbitrarily nested Pydantic models — the model receives a complete JSON schema and must fill every required field.

SECTION 06

Retry logic and error recovery

import instructor
import anthropic
from pydantic import BaseModel, field_validator

client = instructor.from_anthropic(anthropic.Anthropic())

class PhoneNumber(BaseModel):
    raw: str
    formatted: str

    @field_validator("formatted")
    @classmethod
    def must_be_e164(cls, v: str) -> str:
        import re
        if not re.match(r"^\+\d{10,15}$", v):
            raise ValueError(f"Must be E.164 format (+12125551234), got: {v}")
        return v

# Instructor will retry up to 3 times if the validator raises
result = client.messages.create(
    model="claude-3-5-haiku-20241022",
    max_tokens=128,
    max_retries=3,          # ← Instructor retry count
    messages=[{"role":"user","content":"My US number is (212) 555-1234"}],
    response_model=PhoneNumber,
)
print(result.formatted)  # +12125551234

On each retry, Instructor sends the validation error as a new user message: "Validation failed: formatted — Must be E.164 format (+12125551234), got: (212) 555-1234. Please fix and return the corrected JSON."

SECTION 07

Async and streaming

import instructor
import anthropic
import asyncio
from pydantic import BaseModel

# Async client
async_client = instructor.from_anthropic(anthropic.AsyncAnthropic())

class Summary(BaseModel):
    headline: str
    key_points: list[str]
    word_count: int

async def summarise(text: str) -> Summary:
    return await async_client.messages.create(
        model="claude-3-5-haiku-20241022",
        max_tokens=512,
        messages=[{"role":"user","content":f"Summarise:\n{text}"}],
        response_model=Summary,
    )

# Streaming partial objects (shows fields as they're generated)
from instructor import Partial

async def stream_summary(text: str):
    async for partial in async_client.messages.stream(
        model="claude-3-5-haiku-20241022",
        max_tokens=512,
        messages=[{"role":"user","content":f"Summarise:\n{text}"}],
        response_model=Partial[Summary],
    ):
        print(partial)  # prints partial object as fields populate
SECTION 08

Gotchas

Retry cost adds up. Each retry is a full LLM call. With max_retries=3 and a flaky validator, you could pay 3× the expected cost. Write validators that are achievable given the input — don't require E.164 phone numbers if the input text only has informal formats.

Optional fields need defaults. If a field is Optional[str] without = None, Pydantic v2 will raise a validation error when the model omits it. Use Optional[str] = None consistently.

Large schemas increase prompt length. Instructor converts your Pydantic model to a JSON schema that goes into the prompt (or tool definition). A model with 30 fields is a large tool definition — factor this into your token budget.

Field descriptions matter. Use Field(description="...") for every field. The model uses these descriptions to understand what to extract — vague field names produce vague results.
