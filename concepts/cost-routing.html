Cost-Aware Routing

Dynamically routing requests to cheaper models when they are sufficient, and expensive models when quality demands it — automatically optimising the cost/quality tradeoff at scale.

Typical savings
40–70%
Quality delta
<3%
Key signal
query complexity

SECTION 01
('The Cost Problem', 'At scale, every unnecessary GPT-4o call is waste. A 7B local model costs 50–200× less per token than GPT-4o. The challenge: not all queries need GPT-4o. Simple factual lookups, classification tasks, and short reformulations can be handled by smaller models. Cost-aware routing captures these savings without degrading quality on hard queries.')
SECTION 02
('Routing Signals', "Query complexity proxies: token count (long = harder), presence of reasoning keywords ('why', 'explain', 'compare'), detected task type (classification = easy, open-ended = hard), user tier (premium users always get the best model), and historical accuracy of small model on similar queries. Combine multiple signals for a robust routing score.")
SECTION 03
('Classifier-Based Router', 'A lightweight classifier (logistic regression or small BERT) predicts whether the small model "\n "will produce acceptable quality. Train on labelled examples where human raters compared "\n "small vs large model outputs.\n\nfrom sklearn.linear_model import LogisticRegression\nfrom sklearn.feature_extraction.text import TfidfVectorizer\nimport numpy as np\n\n# Assume labels: 1 = small model sufficient, 0 = needs large model\nvectorizer = TfidfVectorizer(max_features=5000, ngram_range=(1, 2))\nclassifier = LogisticRegression(C=1.0)\n\ndef train_router(queries: list[str], labels: list[int]):\n X = vectorizer.fit_transform(queries)\n classifier.fit(X, labels)\n\ndef route(query: str, threshold: float = 0.75) -> str:\n X = vectorizer.transform([query])\n prob_small_ok = classifier.predict_proba(X)[0][1]\n if prob_small_ok >= threshold:\n return "small" # e.g. gpt-4o-mini or local 7B\n return "large" # e.g. gpt-4o')
SECTION 04
('Rule-Based Routing', 'Simple rules often capture 80% of the savings with zero training overhead. "\n "Route to small if: query < 50 tokens, task type is classification/sentiment/extraction, "\n "or user is on free tier. Always use large for: multi-step reasoning, code generation, "\n "medical/legal domains, or when the user explicitly requests it.\n\ndef rule_router(query: str, task_type: str, user_tier: str) -> str:\n # Hard overrides\n if user_tier == "premium":\n return "large"\n if task_type in ("classification", "sentiment", "extraction", "translation"):\n return "small"\n # Heuristic complexity\n if len(query.split()) < 30 and "?" not in query:\n return "small"\n keywords = {"explain", "compare", "analyze", "why", "how does", "what would happen"}\n if any(kw in query.lower() for kw in keywords):\n return "large"\n return "small" # default to cheap')
SECTION 05
('A/B Testing Routes', 'Before deploying a new routing policy, run a shadow A/B test: route 5% of traffic to the new policy and compare quality scores (LLM judge + user signals). Only cut over if quality delta is within your tolerance (typically <5% CSAT drop). Keep the old policy as a fallback for 2 weeks after cutover.')
SECTION 06
('Monitoring Costs', 'Track: cost per request by model, routing distribution (% to each model), quality score by routed model, and cost savings vs always-large baseline. Alert if: cost per request increases >20% (routing shifted to large), or quality score for small-routed requests drops >5% (router over-routing).')
