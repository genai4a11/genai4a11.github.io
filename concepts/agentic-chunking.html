Agentic Chunking

A document chunking strategy that uses an LLM to determine chunk boundaries based on content coherence — producing semantically complete, variable-length chunks without fixed window sizes.

SECTION 01
('What Is Agentic Chunking?', 'Agentic chunking uses an LLM as a document understanding agent: it reads the document and decides where to split based on semantic coherence — keeping related content together and splitting at natural topic boundaries. The result is variable-length chunks that respect document structure: a code block stays with its explanation, a table stays with its header row.')
SECTION 02
('The Chunking Algorithm', "The LLM is given the document (or a rolling window of it) and asked: 'Is this content complete as a standalone chunk, or does it need more context?' If complete, split here. If not, include the next paragraph and re-evaluate. This produces chunks that are semantically complete — each chunk answers a coherent question without requiring surrounding context.")
SECTION 03
('Implementation', 'from openai import OpenAI\n\nclient = OpenAI()\n\ndef agentic_chunk(document: str, target_size: int = 500) -> list[str]:\n paragraphs = document.split("\\n\\n")\n chunks = []\n current = []\n current_len = 0\n\n for para in paragraphs:\n current.append(para)\n current_len += len(para.split())\n\n if current_len >= target_size:\n # Ask LLM if current accumulation is a coherent chunk\n candidate = "\\n\\n".join(current)\n response = client.chat.completions.create(\n model="gpt-4o-mini",\n messages=[{\n "role": "user",\n "content": (\n "Is the following text a semantically complete, standalone unit? "\n "Reply with YES or NO.\\n\\n" + candidate[:1000]\n )\n }],\n max_tokens=5,\n temperature=0,\n )\n if "YES" in response.choices[0].message.content.upper():\n chunks.append(candidate)\n current = []\n current_len = 0\n\n if current:\n chunks.append("\\n\\n".join(current))\n return chunks')
SECTION 04
('When to Use', 'Use agentic chunking for: heterogeneous documents (technical manuals, reports with mixed content), documents where structure matters (code + explanation, tables + captions), and high-value corpora where retrieval quality justifies indexing cost. Avoid for: homogeneous text corpora (news articles), cost-sensitive pipelines, or real-time indexing.')
SECTION 05
('Comparison Table', 'Fixed-size: O(1) cost, low quality, good baseline. Recursive character: O(1) cost, medium quality, respects some structure. Semantic: O(n·embedding) cost, good quality for narrative. Proposition: O(n·LLM) cost, best precision for factoid QA. Agentic: O(n·LLM) cost, best coherence for complex documents. Choose based on the tradeoff between indexing cost and retrieval quality requirements.')
SECTION 06
('Combining with Propositions', 'A powerful two-stage pipeline: (1) Agentic chunking produces semantically complete parent chunks. (2) Proposition extraction produces fine-grained retrieval units from each chunk. At retrieval time, propositions are retrieved for precision; parent chunks are returned for context richness. This is the highest-quality RAG retrieval strategy, at the highest indexing cost.')
