SECTION 01

Why LangGraph

LangChain chains are fundamentally acyclic—they represent linear pipelines: input → model → output → next step → output. This works for RAG, simple chains, and tools but breaks down when you need agents that can make decisions, loop back, branch conditionally, or maintain complex state across multiple turns.

The Problem with Linear Chains

  • No loops: Agent can't iterate—"Did my tool call work? Should I try again?"
  • No branching: Can't conditionally route based on runtime values
  • No explicit state: State flows implicitly through function returns
  • Hard to debug: Unclear what's happening at each step
  • No built-in checkpointing: Can't pause, inspect, resume, or audit long-running executions

LangGraph Solution LangGraph models agentic systems as directed graphs where nodes are functions and edges are state transitions. This enables:

  • Cycles: Loop until stopping condition (agent decides to stop, max iterations, error)
  • Conditional routing: "If X, go to node A; else go to node B"
  • Explicit state: All data flows through a structured state schema
  • Persistence: Checkpoint after each node—resume from any point
  • Human approval: Pause execution, get human input, resume with new state
  • Observability: Each node and edge is visible for debugging and monitoring
Core Insight: Agents are just state machines. LangGraph lets you define them explicitly as graphs rather than hiding control flow inside nested loops and conditionals.
SECTION 02

Core Concepts

LangGraph has a few key building blocks:

1. StateGraph

The container for your graph. You define a state schema (a TypedDict or Pydantic model) that flows through all nodes.

2. State Schema

A Python TypedDict or Pydantic model defining what data moves through the graph:

from typing import TypedDict, Annotated from langgraph.graph import StateGraph class AgentState(TypedDict): messages: Annotated[list, "conversation history"] user_query: str tools_used: list[str] final_answer: str iterations: int # Now you build a graph with this state graph = StateGraph(AgentState)

3. Nodes

Functions that take state and return updated state. Each node runs a step of your system:

def agent_node(state: AgentState) -> AgentState: """LLM decides what to do next.""" messages = state["messages"] response = model.invoke(messages) return { **state, "messages": messages + [response], "iterations": state["iterations"] + 1 } def tool_node(state: AgentState) -> AgentState: """Execute the tool the agent chose.""" last_message = state["messages"][-1] tool_name = last_message.tool_calls[0]["name"] tool = tools_by_name[tool_name] result = tool.invoke(...) return { **state, "messages": messages + [result], "tools_used": state["tools_used"] + [tool_name] }

4. Edges

Transitions between nodes. Can be static (always go to B after A) or conditional (if X go to B, else go to C):

# Static edge graph.add_edge("agent", "tools") # Conditional routing def should_continue(state: AgentState): messages = state["messages"] last_message = messages[-1] if "tool_calls" in last_message: return "tools" # Go to tools node else: return "end" # End execution graph.add_conditional_edges( "agent", should_continue, { "tools": "tools", "end": END } )

5. Compilation & Execution

Once you build the graph, compile it and invoke with initial state:

compiled_graph = graph.compile() initial_state = AgentState( messages=[], user_query="What's the weather?", tools_used=[], final_answer="", iterations=0 ) result = compiled_graph.invoke(initial_state) print(result["final_answer"])
Philosophy: Graphs are explicit. You can draw them on paper, understand the flow, and reason about behavior. This clarity is essential for agents in production.
SECTION 03

Building Your First Graph

Let's build a complete research agent using LangGraph:

from langgraph.graph import StateGraph, END from typing import TypedDict, Annotated from langchain_openai import ChatOpenAI class ResearchState(TypedDict): query: str web_results: str analysis: str final_report: str graph = StateGraph(ResearchState) model = ChatOpenAI(model="gpt-4") def research_node(state: ResearchState) -> ResearchState: """Search the web for information.""" web_results = search_web(state["query"]) return {...state, "web_results": web_results} def analyze_node(state: ResearchState) -> ResearchState: """Analyze the search results.""" prompt = f"Analyze: {state['web_results']}" analysis = model.invoke(prompt).content return {...state, "analysis": analysis} def report_node(state: ResearchState) -> ResearchState: """Generate final report.""" prompt = f"Write report: {state['analysis']}" report = model.invoke(prompt).content return {...state, "final_report": report} # Build graph graph.add_node("research", research_node) graph.add_node("analyze", analyze_node) graph.add_node("report", report_node) graph.add_edge("research", "analyze") graph.add_edge("analyze", "report") graph.add_edge("report", END) graph.set_entry_point("research") # Compile and run compiled = graph.compile() result = compiled.invoke({"query": "Latest AI breakthroughs"}) print(result["final_report"])

Streaming Output

For long-running graphs, stream intermediate results:

for output in compiled.stream(initial_state): for node_name, node_output in output.items(): print(f"{node_name}: {node_output}") # Print each node's state as it completes
Tip: Use .stream() during development to see what's happening at each step. Use .invoke() in production when you only care about the final result.
SECTION 04

Persistence & Memory

One of LangGraph's killer features: built-in checkpointing. Save state after every node, then resume from any point.

SqliteSaver: Local Checkpointing

from langgraph.checkpoint.sqlite import SqliteSaver checkpointer = SqliteSaver(db_path="./langgraph.db") compiled = graph.compile(checkpointer=checkpointer) # First run result = compiled.invoke( initial_state, config={"configurable": {"thread_id": "user-123"}} ) # Later: resume from where we left off result = compiled.invoke( initial_state, config={"configurable": {"thread_id": "user-123"}} ) # Automatically picks up from last checkpoint

Thread-Based Conversation Memory

Each user/conversation gets a unique thread_id. All checkpoints for that thread are saved and retrievable:

# User 1's conversation thread config_1 = {"configurable": {"thread_id": "alice-thread-1"}} compiled.invoke(initial_state, config=config_1) # User 2's conversation thread config_2 = {"configurable": {"thread_id": "bob-thread-1"}} compiled.invoke(initial_state, config=config_2) # Get history of user 1's execution checkpointer = SqliteSaver(db_path="./langgraph.db") states = checkpointer.get_tuple("alice-thread-1") # → List of (config, values, next, checkpoint_id) tuples

PostgreSQL for Production

For scaling to multiple workers, use PostgresSaver:

from langgraph.checkpoint.postgres import PostgresSaver checkpointer = PostgresSaver( conn_string="postgresql://user:pw@localhost:5432/langgraph" ) compiled = graph.compile(checkpointer=checkpointer) # All checkpoints saved to shared DB # Multiple workers can resume same thread
Why Checkpointing Matters: If your LLM API times out, network drops, or you want to pause for human review mid-execution, you can resume exactly where you left off. No re-running expensive steps.
SECTION 05

Human-in-the-Loop

LangGraph natively supports pausing execution to get human approval, feedback, or correction.

interrupt_before: Pause Before a Node

compiled = graph.compile( checkpointer=SqliteSaver(db_path="./langgraph.db"), interrupt_before=["approve_node"] # Pause before approve_node runs ) # Client submits request result = compiled.invoke( initial_state, config={"configurable": {"thread_id": "user-1"}} ) # Execution pauses right before approve_node # Meanwhile, human reviews and approves in UI # Client resumes with human input human_input = {"approval": True, "feedback": "Looks good"} result = compiled.invoke( human_input, # New input merged with checkpointed state config={"configurable": {"thread_id": "user-1"}} )

interrupt_after: Pause After a Node

compiled = graph.compile( checkpointer=checkpointer, interrupt_after=["generate_node"] # Pause after generating output ) # Execution pauses after generate_node completes # State includes the generated content # Human can review and decide next action

Streaming with Interrupts

Stream events and pause for human decision:

for event in compiled.stream( initial_state, config={"configurable": {"thread_id": "user-1"}} ): print(event) # Node completes, pause for human # Server sends "paused" event to UI # UI shows human the state and waits for input # Client resumes: invoke() again with thread_id
Common Pattern: Run agent, pause before critical action (send email, update database), show human the state, get approval, then resume. This is how you add guardrails to autonomous agents.
SECTION 06

Multi-Agent Graphs

LangGraph shines with multi-agent systems. Compose subgraphs, implement supervisor patterns, and route between specialists.

Supervisor Pattern

One agent acts as supervisor, deciding which specialist agent handles each task:

# Specialist agents researcher_agent = build_agent("researcher_tools") analyst_agent = build_agent("analyst_tools") writer_agent = build_agent("writer_tools") agents = { "researcher": researcher_agent, "analyst": analyst_agent, "writer": writer_agent } class SupervisorState(TypedDict): messages: list next_agent: str # supervisor chooses who goes next def supervisor_node(state: SupervisorState) -> SupervisorState: """Route to appropriate specialist.""" messages = state["messages"] # LLM decides: "The researcher should search, then analyst review" decision = model.invoke(messages).content return {...state, "next_agent": decision} graph = StateGraph(SupervisorState) graph.add_node("supervisor", supervisor_node) # Add all specialist agents as nodes for name, agent in agents.items(): graph.add_node(name, agent) # Supervisor decides routing def route_to_agent(state): return state["next_agent"] graph.add_conditional_edges( "supervisor", route_to_agent, {name: name for name in agents.keys()} | {"supervisor": "supervisor"} ) # Everyone loops back to supervisor for name in agents.keys(): graph.add_edge(name, "supervisor") graph.set_entry_point("supervisor")

Subgraphs: Compose Graphs

Reuse a graph as a node in another graph:

# Build inner graph inner_graph = StateGraph(SomeState).compile() # Use as node in outer graph outer_graph = StateGraph(OuterState) outer_graph.add_node("subgraph", inner_graph.invoke) # When outer runs "subgraph" node, it invokes the entire inner graph

Team of Agents

Multiple agents working in parallel on subtasks, then a coordinator combines results:

from concurrent.futures import ThreadPoolExecutor def parallel_agents_node(state: TeamState) -> TeamState: """Run multiple agents in parallel.""" subtasks = state["subtasks"] with ThreadPoolExecutor() as executor: futures = { executor.submit(agent.invoke, task): task for task in subtasks } results = {task: future.result() for task, future in futures.items()} return {...state, "agent_results": results}
Why Graphs for Multi-Agent: Instead of hand-coding orchestration logic, let LangGraph manage agent lifecycle, state passing, and retries. The graph is your spec.
SECTION 07

LangGraph vs Alternatives

How does LangGraph compare to other agent frameworks?

Framework Model State Persistence Best For
LangGraph Explicit state graph Typed schema (TypedDict/Pydantic) Built-in checkpointing (SQLite/Postgres) Complex agents, production systems, transparency
CrewAI Role-based agents with tools Implicit (task → agent → output) Limited Simple multi-agent teams, quick prototypes
AutoGen Conversational agents, human-in-loop Implicit conversation history None built-in Multi-agent debate, interactive systems
Raw LangChain Chains (acyclic) Implicit (flow through chain) None Simple RAG, linear pipelines

When to Choose LangGraph:

  • You need explicit control over agent behavior (loops, branches, state)
  • Production requirements: resumability, auditability, human approval
  • Multi-agent systems where explicit routing and specialization matter
  • You want to test and debug agent behavior step by step

When to Choose Alternatives:

  • CrewAI: Quick prototypes, simple "run N agents in sequence" patterns
  • AutoGen: Interactive multi-agent debate or user-facing conversation
  • Raw LangChain: Simple RAG or chains without agentic loops
Trend: As agents move to production, explicit state graphs (like LangGraph) win over implicit orchestration. You need visibility and control.
