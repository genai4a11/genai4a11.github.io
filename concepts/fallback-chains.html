System Design

Fallback Chains

Ordered sequences of model calls that activate when primary calls fail, timeout, or return low-confidence results — improving reliability without manual intervention.

Reliability uplift
2–3 nines
Latency penalty
50–200 ms
Cost increase
5–15%

SECTION 01
('What Is a Fallback Chain?', 'A fallback chain is a prioritised list of alternatives: if step N fails, try step N+1. The primary model is typically the best available (GPT-4o, Claude Opus); fallbacks are cheaper, faster, or from different providers. The chain handles provider outages, rate-limit errors, timeout breaches, content-filter rejections, and quality thresholds.')
SECTION 02
('Failure Triggers', 'Hard failures: HTTP 5xx, timeout, rate-limit (429), context-length exceeded. Soft failures: response confidence below threshold, output fails a format check, toxicity detected, latency SLA breached. Hard failures trigger the chain immediately; soft failures may retry once before escalating.')
SECTION 03
('Chain Design Patterns', 'Provider fallback: primary OpenAI → fallback Anthropic → tertiary Cohere. "\n "Model-tier fallback: GPT-4o → GPT-4o-mini → cached response. "\n "Strategy fallback: full generation → retrieval-augmented → template-based. "\n "Quality fallback: if confidence < 0.6 → re-prompt with CoT → escalate to human.\n\nTypical priority ordering:\nPRIMARY: GPT-4o (quality=high, cost=high, p99=3s)\nFALLBACK1: Claude Sonnet (quality=high, cost=medium, p99=2s)\nFALLBACK2: GPT-4o-mini (quality=medium, cost=low, p99=1s)\nFALLBACK3: Cached best-match (quality=variable, cost=~0, p99=10ms)')
SECTION 04
('Implementation', 'import openai, anthropic, time\nfrom typing import Optional\n\nasync def call_with_fallback(prompt: str, max_retries: int = 1) -> str:\n chain = [\n ("openai", lambda: call_openai(prompt)),\n ("anthropic", lambda: call_anthropic(prompt)),\n ("openai_mini", lambda: call_openai_mini(prompt)),\n ]\n last_error = None\n for name, fn in chain:\n for attempt in range(max_retries + 1):\n try:\n result = await asyncio.wait_for(fn(), timeout=5.0)\n if result and len(result) > 10: # basic quality gate\n metrics.record("fallback_chain", provider=name, attempt=attempt)\n return result\n except (openai.RateLimitError, openai.APIStatusError,\n anthropic.RateLimitError, asyncio.TimeoutError) as e:\n last_error = e\n if attempt < max_retries:\n await asyncio.sleep(0.5 * (attempt + 1))\n raise RuntimeError(f"All fallbacks exhausted. Last error: {last_error}")')
SECTION 05
('Cost vs Reliability', 'Fallback chains add cost only when triggered. A 99.9% primary success rate means fallbacks fire 1 in 1000 requests — negligible cost for huge reliability gain. For soft fallbacks (quality threshold), tune carefully: too aggressive and costs spiral; too lenient and quality degrades. A/B test the threshold against user satisfaction metrics.')
SECTION 06
('Observability', 'Track: fallback_rate per provider, reason (timeout/quality/error), latency delta, and cost delta. Alert on elevated fallback rates — they indicate provider issues or prompt regressions. A 5% fallback rate to the secondary provider might mean the primary is degraded and you should investigate.')
