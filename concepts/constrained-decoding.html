SECTION 01
('The Parsing Problem', 'Prompting a model to output JSON works ~90% of the time. The remaining 10% produces invalid JSON, truncated objects, or prose with JSON embedded. At scale, 10% failure means constant retries, error handlers, and dropped requests. Constrained decoding eliminates format errors entirely by controlling which tokens are valid at each generation step.')
SECTION 02
('How Constrained Decoding Works', 'At each decoding step, the model produces logits over its entire vocabulary. Constrained decoding applies a mask that zeros out logits for tokens that would violate the current constraint. Only valid tokens can be sampled. The mask is derived from a state machine (FSM) or grammar that tracks where we are in the output structure. No resampling needed — every output is valid by construction.')
SECTION 03
('Grammar-Based Constraints', 'Context-free grammars (CFGs) define the full syntax of the output language. "\n "llama.cpp\'s GBNF grammar format lets you specify any output structure. "\n "Valid tokens at each step are those consistent with some parse of the grammar from the current state.\n\n# GBNF grammar for a simple JSON object\nGRAMMAR = \'\'\'\nroot ::= object\nobject ::= "{" ws members ws "}"\nmembers ::= pair ("," ws pair)*\npair ::= string ":" ws value\nvalue ::= string | number | "true" | "false" | "null"\nstring ::= "\\"" [^\\"]* "\\""\nnumber ::= [0-9]+\nws ::= [ \\t\\n]*\n\'\'\'\n\n# With llama.cpp Python bindings:\n# llm(prompt, grammar=LlamaGrammar.from_string(GRAMMAR))')
SECTION 04
('JSON Schema Enforcement', 'The most common use case: enforce a Pydantic model or JSON schema. "\n "Libraries like Outlines and Guidance make this one-liner simple.\n\nfrom pydantic import BaseModel\nfrom typing import Literal\nimport outlines\n\nclass ProductReview(BaseModel):\n sentiment: Literal["positive", "negative", "neutral"]\n score: int # 1-5\n summary: str\n issues: list[str]\n\nmodel = outlines.models.transformers("mistralai/Mistral-7B-Instruct-v0.2")\ngenerator = outlines.generate.json(model, ProductReview)\n\nreview = generator(\n "Review: The delivery was fast but the product broke after a week. Rate it."\n)\n# review is guaranteed to be a valid ProductReview instance\nprint(type(review)) # \nprint(review.sentiment) # \'negative\'')
SECTION 05
('Regex & CFG Patterns', 'Regex constraints enforce patterns like phone numbers, dates, or structured codes. "\n "Useful when full schema is overkill.\n\nimport outlines\n\nmodel = outlines.models.transformers("mistralai/Mistral-7B-v0.1")\n\n# Force output to match an ISO date\ndate_generator = outlines.generate.regex(model, r"\\d{4}-\\d{2}-\\d{2}")\ndate = date_generator("When was the French Revolution? Answer with just the year: ")\nprint(date) # e.g. "1789-07-14"\n\n# Force choice from a fixed set\nchoice_gen = outlines.generate.choice(model, ["Yes", "No", "Maybe"])\nanswer = choice_gen("Is Python a compiled language?")\nprint(answer) # "No"')
SECTION 06
('Production Libraries', 'Outlines: best for Hugging Face models, supports JSON schema / regex / CFG, very active community. Guidance: Microsoft library, integrates with Azure OpenAI and local models. llama.cpp GBNF: native to llama.cpp, works with any GGUF model, grammar files are portable. OpenAI response_format: not true constrained decoding but guided via fine-tuning; use json_schema mode for structured outputs with 99%+ compliance.')
