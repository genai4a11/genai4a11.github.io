Proposition Chunking

A retrieval-optimised chunking strategy that splits documents into atomic factual statements (propositions) rather than arbitrary text windows — improving retrieval precision.

Retrieval improvement
15–25% over fixed-size
Chunk size
1–3 sentences
Overhead
LLM extraction pass

SECTION 01

What Is Proposition Chunking?

Proposition chunking (Chen et al. 2023, 'Dense X Retrieval') splits documents into atomic propositions — self-contained factual statements that can be understood without context. Instead of 'The model was introduced in 2023 and uses 70B parameters', you get two propositions: 'The model was introduced in 2023' and 'The model uses 70B parameters'. Each proposition is a retrieval unit, leading to more precise embedding-based retrieval.

SECTION 02

How It Works

Step 1: Pass each document chunk to an LLM with a proposition extraction prompt. Step 2: The LLM returns a list of atomic statements. Step 3: Each statement is embedded and stored with a back-reference to the original chunk. At retrieval time, the most similar propositions are fetched. Optionally, the retrieved propositions are expanded to their parent chunks for richer context.

SECTION 03

Implementation

from openai import OpenAI
import json
client = OpenAI()
def extract_propositions(text: str) -> list[str]:
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{
            "role": "user",
            "content": (
                "Convert the following text into a list of atomic propositions. "
                "Each proposition should be a single, self-contained factual statement. "
                "Return as JSON array of strings.\n\n"
                f"Text: {text}"
            )
        }],
        response_format={"type": "json_object"},
    )
    data = json.loads(response.choices[0].message.content)
    return data.get("propositions", [])
# Example
text = "BERT was introduced by Google in 2018. It uses bidirectional training on the Transformer."
props = extract_propositions(text)
# ["BERT was introduced by Google in 2018.",
#  "BERT uses bidirectional training on the Transformer architecture."]
SECTION 04

Pros and Cons

Pros: higher retrieval precision for factoid queries, no context bleed between unrelated facts in the same paragraph, better handling of multi-fact sentences. Cons: LLM extraction adds cost and latency to indexing, propositions can lose context (a proposition about 'it' needs coreference resolved), and the proposition count is unpredictable.

SECTION 05

When to Use

Use for: knowledge bases with dense factual content, QA systems where retrieval precision matters more than recall, and corpora where the same paragraph contains multiple unrelated facts. Avoid for: narrative content (propositions fragment stories), large corpora where indexing cost is a constraint, or when semantic chunking suffices.

SECTION 06

vs Other Chunking Strategies

Fixed-size chunking: fast, simple, low retrieval precision. Semantic chunking: groups related sentences, good for narrative. Proposition chunking: best retrieval precision, highest indexing cost. A practical hybrid: semantic chunk first, then extract propositions per chunk for domains where precision is critical.
