SECTION 01
('Long Context vs RAG', "128K+ context windows allow stuffing entire codebases, documents, or conversation histories into a single prompt. This simplifies architecture — no retrieval pipeline, no chunking, no embedding management. But it doesn't eliminate the need for retrieval; it changes the tradeoff: RAG is cheaper and faster for large corpora; long context is simpler and more accurate for moderate corpora.")
SECTION 02
('Lost-in-the-Middle', "Research (Liu et al. 2023) shows models perform worse on information placed in the middle of long contexts compared to information at the start or end — the 'lost-in-the-middle' effect. Mitigation: place most important context at the start and end, not the middle. Use a reranker to select the top K most relevant chunks and place them first.")
SECTION 03
('Cost & Latency Implications', 'Attention is O(n²) in sequence length; a 128K context is 16× more compute than 32K. API costs scale linearly with input tokens at minimum. At $15/M tokens (GPT-4o), a 128K context call costs ~$2 — fine for one-off analysis, ruinous for high-volume chat. Profile: measure cost per request at your expected context distribution.')
SECTION 04
('When to Use Full Context', 'Full-context is a good fit for: document analysis (financial reports, legal contracts), code review (entire codebase in context), long-running conversation with rich history, and tasks requiring global reasoning (summarisation across many sources). Avoid for: high-volume Q&A where only 2–3 chunks are relevant, and cost is a constraint.')
SECTION 05
('Hybrid Architectures', 'Combine retrieval for first-pass filtering with long context for deep analysis. "\n "Step 1: embed and retrieve top 20 chunks (~10K tokens) relevant to the query. "\n "Step 2: if any chunk scores very high, use only it (cheap). "\n "Step 3: if confidence is low or task is complex, expand to full document (long context mode).\n\ndef select_context_strategy(query: str, docs: list, confidence: float) -> str:\n if confidence > 0.85:\n return "short" # 1-2 chunks, <4K tokens\n elif confidence > 0.60:\n return "medium" # top-10 chunks, ~10K tokens\n else:\n return "long" # full document, 128K tokens')
SECTION 06
('Quality Monitoring', 'Monitor: answer relevance as a function of context length (does quality degrade at >64K?), latency percentiles (p50/p99 at each context tier), and cost per request by tier. Set budget alerts at context thresholds. Run monthly evals comparing short-context RAG vs long-context on your specific workload — the optimal strategy shifts as models and prices evolve.')
