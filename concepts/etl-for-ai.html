ETL for AI

Extract-transform-load pipelines adapted for AI data: ingesting raw documents and converting them to clean, chunked, embedded, and indexed data ready for LLM retrieval.

5–8
Throughput

SECTION 01
('AI ETL vs Traditional ETL', 'Traditional ETL moves structured data between databases. AI ETL handles: unstructured documents (PDFs, HTML, code), extraction of text + structure from arbitrary formats, semantic chunking and embedding, and vector index population. The key difference: every transformation step can degrade quality — a poor PDF parser produces garbled text that no LLM can recover from.')
SECTION 02
('Extraction Layer', 'Parse raw documents into clean text + structure. "\n "Use specialised parsers: Unstructured.io for PDFs/Office/HTML, "\n "BeautifulSoup for web pages, tree-sitter for code. "\n "Extract tables as structured data, images as captions (via vision model), "\n "and preserve heading hierarchy for context.\n\nfrom unstructured.partition.auto import partition\n\ndef extract_document(file_path: str) -> list[dict]:\n elements = partition(filename=file_path, strategy="hi_res")\n chunks = []\n current_section = ""\n for elem in elements:\n if elem.category == "Title":\n current_section = str(elem)\n elif elem.category in ("NarrativeText", "ListItem", "Table"):\n chunks.append({\n "text": str(elem),\n "section": current_section,\n "type": elem.category,\n "metadata": elem.metadata.to_dict(),\n })\n return chunks')
SECTION 03
('Transformation Layer', 'Clean: remove boilerplate headers/footers, fix encoding issues, normalise whitespace. Chunk: split into retrieval-sized pieces (200–800 tokens) with overlap (10–20%). Enrich: add metadata (doc title, section, source URL). Embed: convert text to vectors (OpenAI text-embedding-3-small or local model). Each step should be idempotent and independently testable.')
SECTION 04
('Loading & Indexing', 'Batch-upsert to your vector store with document_id + chunk_index as the unique key. "\n "Upsert (not insert) so re-runs don\'t create duplicates. "\n "Update the metadata catalogue (Postgres/DynamoDB) with ingestion timestamp.\n\nfrom openai import OpenAI\nfrom qdrant_client import QdrantClient\nfrom qdrant_client.models import PointStruct\nimport uuid\n\noai = OpenAI()\nqdrant = QdrantClient("localhost", port=6333)\n\ndef embed_and_load(chunks: list[dict], collection: str):\n texts = [c["text"] for c in chunks]\n embeddings = oai.embeddings.create(\n model="text-embedding-3-small", input=texts\n ).data\n points = [\n PointStruct(\n id=str(uuid.uuid4()),\n vector=emb.embedding,\n payload=chunks[i],\n )\n for i, emb in enumerate(embeddings)\n ]\n qdrant.upsert(collection_name=collection, points=points)\n return len(points)')
SECTION 05
('Orchestration', 'Use a workflow orchestrator (Airflow, Prefect, Dagster) to schedule and monitor ETL runs. Structure as a DAG: extract → validate → chunk → embed → load → verify. Checkpoint each stage so failed runs resume from the last successful step. Monitor: documents processed/hour, embedding cost, index size, and error rate.')
SECTION 06
('Incremental Updates', "Full re-ingestion is expensive. For incremental updates: hash each document on ingest, store in a manifest table. On re-run, skip documents whose hash hasn't changed. Delete + re-embed only changed or new documents. For deleted source documents, implement a soft-delete: mark as inactive in the manifest, purge from the index on next cleanup run.")
