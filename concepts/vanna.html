Vanna AI

An open-source RAG-based Text-to-SQL framework that improves accuracy by retrieving similar past queries and schema documentation as context before generating new SQL.

Approach
RAG + LLM
Training data
DDL + docs + Q/SQL pairs
Backends
any LLM + any DB

SECTION 01

How Vanna Works

Vanna uses RAG to improve Text-to-SQL accuracy: it stores DDL (CREATE TABLE statements), documentation, and example (question, SQL) pairs in a vector store. When a new question arrives, it retrieves the most relevant DDL and examples and includes them in the prompt. The LLM generates SQL with this rich context. The more examples you train it on, the better it gets.

SECTION 02

Training Vanna

Train Vanna by adding DDL, documentation, and example pairs. " "This is a one-time setup + ongoing improvement process.

import vanna
from vanna.openai import OpenAI_Chat
from vanna.chromadb import ChromaDB_VectorStore
class MyVanna(ChromaDB_VectorStore, OpenAI_Chat):
    def __init__(self, config=None):
        ChromaDB_VectorStore.__init__(self, config=config)
        OpenAI_Chat.__init__(self, config=config)
vn = MyVanna(config={"api_key": "your-key", "model": "gpt-4o"})
# Add schema knowledge
vn.train(ddl="CREATE TABLE orders (id INT, customer_id INT, amount FLOAT, date DATE);")
vn.train(documentation="The orders table contains all purchase records.")
# Add example pairs (most impactful for accuracy)
vn.train(question="How many orders were placed last month?",
         sql="SELECT COUNT(*) FROM orders WHERE date >= DATE_TRUNC('month', NOW() - INTERVAL '1 month')")
SECTION 03

Querying

Once trained, a single call generates, executes, and explains the result.

# Connect to database
vn.connect_to_postgres(host="localhost", dbname="mydb", user="user", password="pass")
# Generate and run SQL
sql = vn.generate_sql("What are the top 10 customers by total spend?")
print(sql)  # SELECT customer_id, SUM(amount) as total... ORDER BY total DESC LIMIT 10
df = vn.run_sql(sql)
# Or do it in one call
df, fig, _ = vn.ask("What are the top 10 customers by total spend?")
fig.show()  # auto-generated chart!
SECTION 04

Model & DB Support

LLMs: OpenAI, Anthropic, Google Gemini, Mistral, Ollama (any local model). Vector stores: ChromaDB, Qdrant, Pinecone, Weaviate, OpenAI Embeddings. Databases: PostgreSQL, MySQL, SQLite, BigQuery, Snowflake, DuckDB, and more. Mix and match: use Ollama + ChromaDB for a fully local, private setup.

SECTION 05

Self-Hosted vs Cloud

Self-hosted (open-source): full control, data stays on-premise, unlimited training examples. Vanna.ai cloud: hosted with a UI for training and querying, team collaboration features. For enterprise/regulated environments, self-hosted is the right choice.

SECTION 06

Comparison to Direct Text-to-SQL

Direct Text-to-SQL: simple, no training required, works out of the box for simple schemas. Vanna: requires upfront training, significantly more accurate for complex schemas and queries, improves over time as more examples are added. The break-even point is roughly 10+ tables or when direct approaches hit 70% accuracy — at that point, Vanna's RAG approach pulls noticeably ahead.
